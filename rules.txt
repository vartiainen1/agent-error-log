2) HOW I WORK
================================================================================
- ERROR-HANDLING PROTOCOL (MANDATORY): when you encounter an error, do NOT
  fix it immediately. FIRST log it in errors.txt (template at its end).
  ONLY after it is logged are you allowed to fix it. Log first, fix after —
  always, no exceptions.
  Tooling: `python check_errors.py` validates the log; `--has-entry "<AREA>"`
  gates a fix (exit 0 only if the error is already logged); `--add` scaffolds
  a new entry in the template format; `--archive-days N` archives old FIXED
  entries (preview only unless --apply).
  Git gate: this folder is a git repo; the commit-msg hook
  (git-commitmsg-hook.sh, installed as .git/hooks/commit-msg) blocks code
  commits whose message lacks an "AREA: <text>" marker matching a logged
  entry — write: git commit -m "... (AREA: <what broke>)".
- SESSION START: at the beginning of every session, run `python start.py`
  (Windows: double-click start.bat) to print the reading order, the mandatory
  rules, the open errors and the latest session note.
- CHECK-BEFORE-CODING PROTOCOL (MANDATORY): before writing or modifying ANY
  code, review errors.txt FIRST so you do not repeat past mistakes. Read the
  log, note the errors relevant to what you are about to write, and avoid
  them.
- Follow existing project conventions. Read the surrounding code, tests, and
  config BEFORE writing anything. Never invent conventions of your own.
- Make the SMALLEST change that satisfies the request. No gold-plating, no
  speculative refactors, no unrequested cleanup.
- Reuse existing helpers/functions instead of reimplementing them.
- If a library or service is needed, verify it exists in the project
  (requirements, package.json, imports) or research it before using it.
- When you change an exported symbol, update every reference to it.
- Don't surprise the user: no destructive commands, no production changes,
  no committing/pushing unless explicitly asked.
- Ask for clarification when the request is ambiguous or the options are
  meaningfully different.

7) LESSONS LEARNED FROM THE ERROR LOG
================================================================================
Distilled root causes from errors.txt (see that log for the full
symptom -> cause -> fix per entry). Re-read these before coding — they are
WHY past errors happened, and what to avoid repeating.

The five starter lessons below are generic root-cause patterns worth keeping.
Replace them with YOUR OWN causes as your log grows.

1. DATA ROBUSTNESS
   - Missing dict keys -> KeyError; csv.DictReader fills missing columns
     with None -> None.strip() crashes.
   - Use row.get('amount', 0) / (row.get(...) or '').strip(); check a key
     exists and is not None before operating on any value.

2. LLM MODEL QUIRKS (your provider/model)
   - Baked-in system-prompt / template guidance can be INERT (byte-identical
     output) — verify, don't assume.
   - Verbose tool descriptions and system messages that name tools push the
     model into XML/prose instead of JSON tool calls; it may hallucinate
     tool names and malformed arguments.
   - Fix behavior in the prompt itself; keep tool definitions short and
     factual; keep the system prompt generic; handle multiple output styles
     with retries.

3. ENVIRONMENT / RELIABILITY
   - Search engines and APIs throttle back-to-back queries; keep gaps and
     fallbacks.
   - Wrong Python (venv missing a package) breaks scripts; PATH order can
     pick the wrong interpreter — call the right one explicitly.
   - Derived models / built artifacts may not exist; keep automatic
     fallbacks with readable messages.

4. SCREEN-VISION (GAME / UI AUTOMATION)
   - Saved sprite colors drift from the live sprite; trackers glue to UI
     blobs — rediscover colors during verified live runs; reject oversized
     and edge (UI) blobs.
   - OCR misreads fake on-screen clocks — require additional signals
     (e.g. motion) and sanity clamps.
   - Modal screens ignore Enter/Space cycling — press explicit keys.
   - Repeated identical actions loop forever — fingerprint actions and
     break after N repeats.

5. LOG / TEMPLATE DISCIPLINE
   - Unenforced entries drift (ERROR v1:, FIX (works):, missing CAUSE) and
     become unparseable — use check_errors.py (--add / --has-entry /
     validate) so the log stays machine-readable.
